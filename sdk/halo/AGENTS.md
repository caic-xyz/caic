# Halo SDK

Kotlin/Android SDK for Brilliant Halo (and Frame) smart glasses over Bluetooth LE.
Mirrors the [Brilliant SDK](https://github.com/brilliantlabsAR/brilliant_sdk) in native
Kotlin using `android.bluetooth.le`.

See [PROTOCOL.md](PROTOCOL.md) for the full BLE protocol reference, wire formats, and source
mappings.

## Architecture

```
Host App
  └── com.caic.halo.msg  —  typed messages (sprites, text, IMU, photos, clicks, audio)
      └── com.caic.halo.ble  —  BLE transport (connect, MTU-aware chunking, Lua REPL)
          └── Android Bluetooth LE
              └── Halo device (Lua VM + frame.* API)
```

## Module

Gradle module `:halo-sdk` at `sdk/halo/`:

```kotlin
dependencies { implementation(project(":halo-sdk")) }
```

## Design Decisions

**Channel + `receiveAsFlow()` for test notifications.** `MutableSharedFlow(replay=0)` drops
values emitted before a collector starts. `Channel.UNLIMITED` buffers values and delivers
to cold flow collectors — matches send-then-receive pattern.

**`open` class with protected overridable methods.** `BluetoothGatt` has no settable
callback. Tests subclass `HaloConnection` and override `connectGatt()`, `createHaloDevice()`,
`wireWriteSink()`, and `onMtuNegotiated()` to inject test doubles.

## Test Strategy

| Layer | Approach |
|-------|----------|
| Pure logic (`HaloServiceDiscovery`, bit packing, Rx parsers) | JVM unit tests with Robolectric |
| Flow-based logic (`HaloDevice` send/receive) | JVM unit tests, `Channel`-backed notification flow |
| GATT integration (`HaloConnection` lifecycle) | Subclass-override tests |
| Actual BLE I/O | Deferred until real device (instrumented tests) |

## Deferred

- `TxTextPage` + `CircularTextLayout` — needs font rasterization engine
- `TxCaptureSettings` / `TxAutoExpSettings` — complex camera config structs
- `RxTap` / `RxMeteringData` — Frame-specific
- LC3 codec — needs `liblc3` via JNI; PCM suffices for now
- DFU/OTA firmware update — SMP protocol
