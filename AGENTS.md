# AGENTS.md

Development guidelines for the caic project.

For specific guidelines, see:

- [CI/CD Guidelines](.github/AGENTS.md) - Read before editing GitHub Actions
- [Backend Guidelines](backend/AGENTS.md) - Read before editing Go code in backend/
- [Frontend Guidelines](frontend/AGENTS.md) - Read before editing frontend code

Run `make` for the current targets; each slow or environment-dependent target
documents its cost beside its definition.

## Project Overview

caic manages multiple coding agents in parallel. Each task runs in an isolated [md](https://github.com/caic-xyz/md) container with Claude Code communicating via streaming JSON over SSH.

### Frontend / Go Mode Boundary

`frontend/` (SolidJS) owns caic screen-mode product UI. The standalone
`github.com/gomodedev/gomode` repository owns the Android shell around
backend-hosted frontends. caic task-list/detail/diff/widget UI stays in the
hosted web frontend.

### Serialized Structures

Define serialized structures in dedicated schema packages, separately from
runtime logic. API DTOs belong in `backend/internal/server/api/v1`; owned
storage formats belong in the owning component's `data` package. This includes
logs, caches, and temporary disk spools. See the
[backend serialization rules](backend/AGENTS.md#serialized-structures).

### Versioned Contracts

Every wire API and serialized format has a version. Wire APIs are HTTP routes,
SSE and WebSocket events, MCP tools, resources and cursors, and SDK types.
Serialized formats are the files, logs, caches, spools, cookies, and browser
storage that caic writes. A route path, file path, or `version` field holds the
version; a format without one is version 1.

A breaking change ships as version N+1 beside version N:

- Breaking: remove or rename a field, route, or enum value; change a type,
  unit, default, or meaning; make an optional field required; reject input
  that version N accepts. Adding an optional field or a route is not breaking.
- Copy the vN package to vN+1 and change the copy: `api/v2` beside `api/v1`,
  `data/v4` beside `data/v3`.
- Use the vN types directly. Do not declare type, constant, or variable
  aliases or forwarding wrappers for them; saving churn does not justify an
  alias.
- Move clients and writers to vN+1. Serve and read vN through an adapter over
  the current implementation.
- Mark each vN declaration and adapter with
  `TODO(YYYY-MM-DD): delete vN once this date has passed and two release tags contain vN+1.`
  The date is the commit date plus 7 days. Count tags with
  `git fetch --tags origin && git tag --contains <commit that added vN+1>`.
- When both conditions hold, delete vN with its adapter, tests, and
  generated SDK.

### Documentation Changes

- **Do NOT** create a markdown file listing changes you made.
- **Do NOT** cite local task IDs in source comments, docs, or test names.
  Describe the evidence instead, e.g. "Minimized from a task log".
- **Always update the purpose comment** at the beginning of a source file when
  the code's purpose changes. This comment is used to generate the file index
  in `AGENTS.md`.

### Professionalism

After changes, run `make fix`, `make verify`, and `make test`. `make fix` also
regenerates the API SDKs, AGENTS indexes, and backend architecture docs.

### Git Hooks

Mandatory: Run `make git-hooks` to install git hooks before making any change.

### Performance

Benchmark when a change could materially affect user-visible latency,
throughput, or memory use. Run the relevant focused benchmark before and after,
add one when needed, and report the delta. Use `make benchmark` for broad
performance work. Mechanical refactors and minor overhead on infrequent paths
do not require benchmarks. Benchmarks requiring local production data remain
documented beside their source and are not part of `make benchmark`.

### E2E Tests

`make test-e2e` runs the Playwright suite against the fake backend server; see
the header of `e2e/playwright.config.ts` for the constraints (frontend-build
sharing, targeted runs, screenshot rendering).

### Smoke Tests

Smoke tests such as `make test-smoke` are optional. They may be skipped,
especially when the running environment lacks the privileges required by the
containers runtime (docker or podman). Report skipped smoke tests and the reason
in the handoff; they are not a completion gate.

## Python tools

Run Python tools and repository scripts with `uv run --locked`.
Run `uv lock` after changing Python dependencies.
