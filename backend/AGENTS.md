# Go Backend Server and Agents

Go backend for caic. Packages under `internal/` are private.

## Conventions

- Pass `context.Context` through all call chains.
- Use subtests (`t.Run`) to group related test cases under a single `Test*` function.
- Before changing a task's terminal state or a lifecycle lock, read the
  incarnation rules in the `taskmgr` package comment
  (`internal/task/taskmgr/manager.go`).

## Serialized Structures

- Define API request, response, and SSE DTOs in `internal/server/api/v1` and
  follow [its dependency boundary](internal/server/api/AGENTS.md). Reuse those
  types rather than defining duplicate wire structures in handlers or services.
- Define caic-owned file, log, cache, and spool schemas in a dedicated `data`
  package beneath the owning component. Use versioned subpackages where the
  format requires compatibility across releases, following existing layouts
  such as `internal/taskslog/data/v3` and `internal/auth/data/v1`.
- Keep schema definitions and serialization tags out of runtime implementation
  packages. This applies to private structs and temporary, rebuildable disk
  formats too. A type alias to a schema-owned type does not create a new schema.
- Keep processing, I/O, and conversions between runtime and serialized types in
  the owning implementation package. Schema packages must not depend on runtime
  implementation types; define the serialized representation in the schema
  package and convert explicitly at the boundary.

## API Verification

Any change to an API DTO, route, handler, or API conversion must run
`make verify` (which typechecks against the generated SDK) and
`make test-e2e` (which verifies the browser-facing API contract against the
fake backend).

## Container Adoption

Adopted containers (preexisting containers found on server restart) have the relay running inside them. This
permits the user to restart the server, e.g. for a software update, without losing their coding sessions.

## Package layering

Packages are grouped under domain umbrellas (`agent/`, `forge/`, `runtime/`,
`repo/`, `task/`). The umbrella is the foundational layer (identity or an
abstraction); nested packages are higher layers or implementations built on it.
Nesting means "built on," not just
"related to": `forge/github` implements `forge`.
